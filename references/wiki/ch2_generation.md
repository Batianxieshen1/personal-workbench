# Ch2 大模型怎样生成回答

## 2.1 自回归生成（"高级文字接龙"）
- 回答不是一次写完的，而是**一个 token 一个 token 接出来**的：根据前面已有的内容预测下一个 token，把它接到后面，再继续预测下一个。这叫**自回归生成（Auto-regressive Generation）**。
- 每一步出现的不是唯一答案，而是**一组候选 + 概率**。如输入"今天天气"，后面可能接"好"、"不错"、"怎么样"、"有点冷"。
- 所以：**同样一句话问两次，回答可能不完全一样**——不是故意变，是生成过程本来就有概率。问题给得越清楚，方向越确定；越模糊，发挥空间越大。
- 示例：问"庞统穿越到落凤坡，心理阴影面积是多少？"——模型识别出这不是数学题，而是在玩梗，会一本正经接梗回答。

## 2.2 token：模型眼里的"文字片段"
- 模型一步步生成的单位是 **token**，不一定等于你眼里的"一个字"或"一个词"。可理解为模型眼里的"文字片段"。
- 为什么模型数不对 strawberry 里的 r？→ 它看到的可能是 str / aw / berry 这样的片段，而不是一个个字母。
- 中文也一样：你眼里是 今 / 天 / 天 / 气 四个字，tokenizer 可能切成 今天 / 天气 两个 token。模型把切分后的片段转换成数字 ID。
- **核心直觉：AI 看到的文字和你看到的并不完全一样。** 后面讲上下文长度、计费、长文处理都会再次遇到 token。

## 2.3 注意力（Attention）
- 问题：模型凭什么根据前面的内容判断下一个 token 更可能是什么？→ **注意力**机制。
- 生成每个 token 时，模型会**回看前面的内容，判断哪些位置更重要**：
  - 看到"公园" → 更容易预测下一个 token 是"散步"；
  - 看到"散步" → 结合"我们 / 去 / 公园"等线索，判断后面更可能接"吧"。
- 模型能顺着上下文生成句子，是因为它在前面的 token 序列之间找到了相关线索。

## 2.4 MoE（Mixture of Experts，混合专家模型）
- 背景：模型越来越大 → 能力增强，但成本、速度、资源消耗也变大。
- 思路：模型内部准备**多组"专家"**，不同专家擅长不同类型信息。每次生成时先判断当前任务需要哪些专家，**只激活一部分**，而不是所有参数都参与计算。
- 类比：学校里的"专家服务台"——语文、数学、物理、英语老师后台待命；问物理题时系统只请物理老师，不叫所有老师。学生体验像在问一个人（快），系统背后多专家分工（省）。
- 架构位置：Decoder Block 可理解为模型内一层层处理 token 的计算单元；MLP/FFN 是其中继续加工信息的部分。**MoE 的变化发生在这里：把原来固定的一块 MLP/FFN，换成多组可选择的专家。**
- 实例：**Qwen3-235B-A22B**——总参数量 235B（约 2350 亿）；每次推理只激活 22B（约 220 亿）。MoE 模型通常：知识容量大、单次计算更省、推理速度更容易优化。
